# 雾城灯塔美术竖切片设计

## 1. 背景与目标

本设计定义剧情模式第一版美术升级竖切片。现有项目已经是 Vue 3、TypeScript、Vite、PixiJS 的网页端游戏，剧情模式已有雾城、灯塔、视野半径和怪物压力等规则。本阶段不重做玩法，只把剧情模式开局区域和中心灯塔周边做成可验证的卡通精细化画面标杆。

最终方向为：

```text
手绘资产 + 图集管线
AI 生成底图 + 人工修图统一风格
保持当前俯视/轻俯视
明亮冒险废土
蓝绿科技信标
```

### 设计目标

- 让剧情模式开局区域从程序图形原型升级为资产驱动的卡通精细画面。
- 验证 AI 生成资产经过人工统一后，是否能稳定接入 PixiJS 图集与动画系统。
- 保留当前剧情模式的移动、碰撞、灯塔交互、视野变化和怪物压力逻辑。
- 建立最小资产规范，为后续玩家、怪物、Boss、地图和特效批量美术化打基础。
- 用一个可玩的场景证明美术方向，而不是先做全游戏重构。

### 非目标

- 不重做经典模式或 Boss Rush。
- 不重做剧情模式完整地图拓扑。
- 不一次性替换所有 Graphics 绘制。
- 不引入 2.5D、等距地图或新的坐标系统。
- 不做复杂 shader 管线；第一版优先使用 Sprite、AnimatedSprite、Container、mask、alpha、scale 和 GSAP 动画。
- 不要求 AI 直接生成完全可用的最终游戏资产；AI 输出需要人工修图、裁切、描边、透明背景和色彩统一。

## 2. 视觉方向

本竖切片采用“明亮冒险废土”。它不是传统灰褐、脏暗、写实末日，而是更清楚、更卡通、更适合高密度战斗阅读的废土城市。

### 关键词

- 粗轮廓。
- 清晰色块。
- 暖色废土背景。
- 蓝绿机甲科技能量。
- 高对比角色和怪物。
- 可读性优先于真实脏污。
- 雾效有层次，不糊成灰屏。

### 色彩基调

地图底色使用暖绿、黄褐和浅灰，表现废土但保持明度。玩家机甲、灯塔、扫描环和关键交互使用蓝绿能量色。怪物使用更高饱和的黄绿、橙红或紫红，确保它们在道路、建筑和雾层上仍然容易识别。

推荐基础色板：

```text
背景暗绿：#202822
道路灰绿：#2E3630
废土黄褐：#746B58
建筑浅绿：#61745E
机甲蓝绿：#68E1FD
科技深青：#2C453F
信标高光：#B9FFF0
警示橙：#FF9F1C
怪物黄绿：#9ECB62
受击红：#FF5B5B
```

### 灯塔情绪

灯塔选择“蓝绿科技信标”。点亮时不表现为篝火或传统安全塔，而是表现为机甲可识别的城市扫描基站：

1. 未点亮：塔体暗、局部蓝绿指示灯微弱闪烁，周围雾浓。
2. 充能：玩家按 E 后，塔底出现蓝绿能量环，塔身分段亮起。
3. 点亮：扫描环向外扩散，雾层被推开，视野半径扩大，建筑和道路细节显现。
4. 压力反馈：点亮后怪物压力提高，远处可以短暂出现更亮的怪物轮廓或警示脉冲，提示“视野变清楚，但城市也醒了”。

## 3. 竖切片范围

只做剧情模式开局区域和中心灯塔周边，目标是一个玩家能进入、移动、点亮灯塔、看到雾和地图变化、遭遇普通怪的短流程。

### 包含内容

- 剧情模式开局街区。
- 中心灯塔及周边道路。
- 先锋机甲玩家形象。
- 1 种普通怪。
- 灯塔未点亮、充能、点亮三态。
- 蓝绿扫描环和雾层变化。
- 少量地图装饰。
- 基础普攻或技能临时特效。

### 暂不包含内容

- 全剧情地图资产化。
- 所有机甲职业差异化外观。
- 所有 Boss 美术替换。
- 室内地图资产化。
- 完整地图 chunk 加载系统。
- Spine 或骨骼动画接入。
- 商店、背包、对话或剧情演出 UI。

## 4. 资产清单

第一批资产必须少而完整，覆盖地图、角色、交互和战斗反馈四类。

### 地图资产

- 道路 tile：直路、裂缝道路、路口边缘。
- 地表 tile：废土地面、草痕、破碎水泥。
- 装饰 sprite：碎石、废车、小路灯、路障、残破广告牌。
- 建筑 sprite：2 到 3 种俯视/轻俯视建筑外观。
- 灯塔底座区域：能量接口、地面线路、破损平台。

地图资产第一版可以只覆盖一个固定区域，不需要无限拼接全地图。每个 tile 建议使用 128x128 或 256x256 PNG。装饰物可以使用 64x64、128x128 或按实际尺寸裁切。

### 角色资产

先锋机甲：

- idle：4 帧。
- run：6 到 8 帧。
- attack：4 帧。
- hit：2 帧。

普通怪：

- idle：4 帧。
- run：6 帧。
- hit：2 帧。
- death：6 帧。

第一版只要求 4 方向：down、up、left、right。若 AI 资产难以稳定生成 4 方向，可以先用 down/right 两方向并镜像 right 得到 left，up 方向使用简化背面剪影。

### 灯塔资产

- lighthouse_off.png：未点亮状态。
- lighthouse_charging.png：充能状态。
- lighthouse_on.png：点亮状态。
- lighthouse_core_glow.png：可叠加发光核心。
- scan_ring.png：扫描环 sprite。

灯塔应有足够大的剪影和交互半径暗示，不能只是一根细小柱子。玩家接近时，它要在雾里仍然可辨认。

### 特效资产

- 子弹或能量弹 sprite。
- 普通命中 spark。
- 蓝绿扫描环。
- 雾纹理或雾噪声贴图。
- 塔点亮爆发光。
- 受击闪白或红色警示小特效。

特效可以半程序化：核心纹理来自 PNG，透明度、缩放、旋转、扩散、屏幕震动和颜色变化由 PixiJS/GSAP 完成。

## 5. AI 资产生产流程

AI 只负责快速产生风格一致的视觉素材基础，不直接保证游戏可用。每类资产都经过人工清理和规范化。

### 流程

```text
风格参考图
  ↓
单资产生成
  ↓
人工修图和统一
  ↓
透明 PNG 导出
  ↓
图集打包
  ↓
Pixi 加载和动画配置
  ↓
游戏内验证
```

### Prompt 约束

每次生成都应固定以下描述：

```text
top-down 2D game asset, bright cartoon wasteland, clean chunky outline,
clear readable shape, stylized hand-painted, high detail but simple silhouette,
blue-green sci-fi energy accents, transparent background when applicable,
no text, no watermark, consistent camera angle
```

地图和灯塔可使用轻俯视描述，但不能生成等距视角：

```text
top-down slightly tilted view, not isometric, readable for action roguelite
```

### 人工统一规则

- 所有角色必须有透明背景。
- 角色轮廓粗细保持一致。
- 同类动作帧的角色中心点保持稳定。
- 同一角色所有帧尺寸一致。
- 不保留 AI 生成的随机文字、徽标、水印和不可读符号。
- 地图 tile 边缘必须能拼接，至少在竖切片区域内不出现明显断缝。
- 所有资产导出前统一亮度和饱和度，避免同一场景里有的像油画、有的像贴纸。

## 6. PixiJS 技术设计

本阶段不大改玩法逻辑，只在剧情模式竖切片引入资产驱动渲染。

### 新增模块

建议新增：

```text
src/visual/assetManifest.ts
src/visual/animationDefinitions.ts
src/visual/storySliceRenderer.ts
src/visual/effects.ts
```

职责：

- `assetManifest.ts`：定义纹理、图集、动画帧路径和加载 key。
- `animationDefinitions.ts`：定义角色动画名称、帧率、循环规则。
- `storySliceRenderer.ts`：创建剧情竖切片地图 sprite、灯塔 sprite、装饰层和雾层。
- `effects.ts`：提供扫描环、点亮爆发、命中特效等可复用效果。

### 接入方式

在 `PixiWastelandGame` 中保留现有玩法状态和 update 循环。剧情模式下，如果当前运行的是美术竖切片区域，则使用新 renderer 创建部分视觉对象：

```text
PixiWastelandGame
  ├─ 继续负责输入、移动、战斗、灯塔交互、指标同步
  ├─ storySliceRenderer 负责地图、灯塔、雾和装饰
  ├─ Actor visual 工厂负责玩家和普通怪 Sprite
  └─ effects 负责点亮和命中反馈
```

第一版不要求完全移除 `Graphics`。可以混合存在：

- 背景和竖切片装饰使用 Sprite。
- 玩家和普通怪使用 AnimatedSprite。
- 未替换的 Boss、弹幕或远处对象继续使用 Graphics。

### 渲染层级

剧情竖切片建议使用固定层级：

```text
groundLayer       地表 tile、道路
decalLayer        裂缝、草痕、污渍
propLayer         废车、路障、路灯、建筑底部
actorLayer        玩家、怪物、Boss
effectLayer       子弹、命中、扫描环、技能
fogLayer          雾层和视野遮罩
uiWorldLayer      世界内提示、交互标记
```

雾层可以放在 actor/effect 之上，但玩家和关键交互物需要保持足够可见。第一版可使用 `Graphics` mask 或半透明 sprite 叠加实现，不必先写 shader。

### 动画和性能

- 使用 `Assets.load` 或 Pixi v8 推荐加载方式预载图集。
- 使用 `AnimatedSprite` 播放玩家和怪物动作。
- 同一图集内的纹理复用，减少 draw call。
- 竖切片地图第一版可以全部常驻内存，因为范围很小。
- 不在每帧创建新 Graphics 或 Sprite；特效对象使用创建后销毁或对象池。

## 7. 玩法行为保持

本阶段必须保留当前剧情模式规则：

- 玩家从剧情模式开局进入雾城。
- 按 E 可以点亮中心灯塔。
- 点亮前 `storyLitLighthouseCount` 为 0。
- 点亮后 `storyLitLighthouseCount` 为 1。
- 点亮后视野半径扩大。
- 点亮后怪物压力倍率提高。
- 现有 HUD 仍显示灯塔、视野和怪物压力信息。
- 返回主界面、重新开始和其他模式不受影响。

视觉变化不能破坏现有测试中对剧情模式的可观测行为。

## 8. 验收标准

### 视觉验收

- 进入剧情模式后，开局区域不再主要依赖纯色 Graphics 地图。
- 玩家机甲和普通怪以 sprite 或 AnimatedSprite 显示。
- 中心灯塔有未点亮、充能、点亮三个明确状态。
- 点亮灯塔时出现蓝绿扫描环扩散。
- 雾层点亮前后有明显区别。
- 地图、角色、灯塔和特效风格统一，不像来自不同素材包。
- 在 1366x768 和移动窄屏下，HUD 不遮挡核心交互对象。

### 技术验收

- `npm test` 通过。
- `npm run build` 通过。
- `npm run e2e` 通过，至少覆盖剧情模式进入、机甲选择、灯塔点亮和 canvas 非空。
- 经典模式和 Boss Rush e2e 不回退。
- 图集和 PNG 资产被 Vite 正确打包。
- 没有明显每帧创建大量对象导致的卡顿。

### 产品验收

- 玩家能在 10 秒内理解“灯塔可交互”。
- 点亮反馈足够强，能明显感到视野被打开。
- 画面更卡通、更精细，但战斗目标仍清楚。
- 美术竖切片足以作为后续全量资产制作的参考标准。

## 9. 实施顺序建议

1. 建立资产目录和 manifest。
2. 准备首批 AI 资产或临时 PNG。
3. 接入剧情竖切片地图背景、道路、装饰和灯塔。
4. 替换玩家机甲为 AnimatedSprite。
5. 替换 1 种普通怪为 AnimatedSprite。
6. 增加蓝绿扫描环、雾层变化和灯塔三态。
7. 更新 e2e 或补充视觉可观测断言。
8. 做截图验收和性能检查。

## 10. 后续扩展

竖切片通过后，再决定是否扩展到：

- 全剧情地图 chunk 化。
- 所有剧情区域 tower 资产。
- 经典模式地图资产化。
- Boss Rush 专属 Boss sprite 和技能特效。
- Spine 或骨骼动画。
- 自动生成 atlas 的脚本和资产校验脚本。
- 更完整的灯光、LUT 或 shader 风格化。
